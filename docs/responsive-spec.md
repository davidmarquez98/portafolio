# Responsive Specification

## Breakpoint philosophy
Mobile-first. Breakpoints should follow content needs, not arbitrary device models.

Suggested Tailwind ranges:
- base: mobile
- md: tablet / small desktop
- lg: desktop
- xl: wide desktop

## Navigation
Mobile:
- logo/name left
- compact menu trigger right
- language and theme controls accessible from menu or compact header

Desktop:
- name/logo left
- section links centered/right
- EN/ES and theme control right
- sticky with subtle background blur after scroll

## Hero
Mobile order:
1. eyebrow
2. headline
3. supporting copy
4. stack
5. CTAs
6. availability
7. portrait

Desktop:
- text dominant on left
- portrait on right
- headline should not be squeezed by portrait

## About
Mobile:
- single column
- stats below copy

Desktop:
- text + compact stats/grid

## Experience
Mobile:
- stacked cards
- dates above role/company
- architecture diagram full-width and horizontally scrollable only if absolutely necessary; prefer reflowing instead

Desktop:
- timeline or two-column detail layout
- maintain comfortable text width

## Selected Work
Mobile:
- content first
- visual/diagram below

Desktop:
- two-column editorial layout

## Expertise
Mobile:
- stacked categories

Desktop:
- two or three-column grid depending on readability

## Contact
Mobile:
- centered or left-aligned depending on final visual review
- CTAs easy to tap

Desktop:
- larger typography with compact social/action row

## Touch & accessibility
- Minimum practical interactive hit area around 44px.
- No hover-only information.
- Menus usable with keyboard.
- Avoid horizontal page overflow.
